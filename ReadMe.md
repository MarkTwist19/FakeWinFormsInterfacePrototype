Project Analysis: "Fake Software Interface"

Core Purpose: To create a narrative prop—a believable, amateur-built Win32/WinForms-style application that appears to be a real (but poorly polished) utility, capable of scripted interactions for a video series.

Key Requirements:

    Aesthetic: "Visually rough," "Win32 UI Windows 7 era," "generic utility without much polish." This is about deliberate "bad" UI, not accidental.

    Faked Functionality:

        Fake Chat: A chat client/server simulation that displays pre-determined messages, likely triggered by user interaction or timers.

        Rigged Feats: The software must behave in specific, pre-programmed ways to advance the plot.

        Hotkey-Triggered Crashes: Specific key combinations should cause designed failure states (specific error messages, freezes, BSOD模仿, etc.).

    Vibe: "Amateur." This suggests inconsistent spacing, mismatched controls, placeholder text, overly verbose or technical error messages, and perhaps unnecessary complexity.
